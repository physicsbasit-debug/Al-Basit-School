# منظومة مسار للاحتياط والتبادل الودي

## 1. التعريف بالمنظومة

منظومة مسار هي تطبيق ويب مدرسي مخصص لتنظيم أعمال الاحتياط والتبادل الودي والجداول اليومية داخل المدرسة، مع دعم الصلاحيات الإدارية وتوثيق العمليات الحساسة وحفظ البيانات بصورة آمنة.

تهدف المنظومة إلى تقليل الجهد اليدوي في توزيع حصص الاحتياط، تحسين العدالة في التكليفات، تسهيل مراجعة أرصدة المعلمين، وتنظيم التبادلات الودية بين المعلمين الحاضرين.

---

## 2. الوظائف الرئيسة

- إدارة الغياب اليومي.
- توزيع حصص الاحتياط.
- عرض جدول اليوم حسب القسم.
- عرض جدول المعلم الأسبوعي.
- إدارة التبادل الودي الأسبوعي.
- متابعة أرصدة الاحتياط.
- متابعة مرات الغياب.
- متابعة حالات التقصير.
- إدارة حالات الإعفاء.
- مركز بيانات مدرسية للملفات المرجعية.
- سجل العمليات الحساسة.
- حفظ آمن للبيانات مع نسخ احتياطية.
- إعدادات مدرسة قابلة للتخصيص عبر ملف `data/school_config.json`.

---

## 3. أدوار الدخول والصلاحيات

| الدور | الصلاحيات العامة |
|---|---|
| مالك النظام | جميع الصلاحيات، بما فيها مركز البيانات والتصفير والإعدادات الحساسة |
| الإدارة | التوزيع، الأرصدة، الإعفاءات، التبادل، الجداول، وتعديل الخزنة الأساسية |
| المعلم الأول / المنسق | التوزيع، الأرصدة، التبادل، جدول اليوم، جدول المعلم |
| الدخول العام | التبادل الودي، جدول اليوم، جدول المعلم فقط |

## 4. هيكل الملفات الحالي

بعد التفكيك المعماري حتى مرحلة `3M-final-safety-note` أصبحت المنظومة مبنية على وحدات واضحة بدل الاعتماد على ملف واحد ضخم. يبقى `app.py` مسؤولًا عن واجهة Gradio والربط والـwrappers، بينما انتقل منطق العمل الثقيل إلى وحدات مستقلة.

| الملف / المجلد | المسؤولية الحالية |
|---|---|
| `app.py` | واجهة Gradio، ربط الأحداث، دوال العرض، وwrappers التي تستدعي الـcores |
| `config.py` | الثوابت العامة والأدوار والأقسام وإعدادات التشغيل الأساسية |
| `storage.py` | التخزين الآمن، الأقفال، ملفات JSON، النسخ الاحتياطية، وسجل التدقيق |
| `auth.py` | الحسابات والصلاحيات وPIN والـcores الخاصة بإدارة الحسابات |
| `distribution.py` | منطق التوزيع والاحتياط، الخزنة، الإلغاء، والتحديثات المرتبطة |
| `school_data.py` | مركز البيانات، الملفات المرجعية، إعدادات التشغيل، وهوية المدرسة |
| `swaps.py` | التبادل الودي، رسائل واتساب، صور/تصدير التبادلات |
| `schedules.py` | جدول اليوم، جدول المعلم، قراءة/عرض الجداول |
| `exemptions.py` | حالات الإعفاء وقواعدها وسجلها |
| `balances.py` | الأرصدة والتقارير المختصرة والجداول المساندة |
| `check_masar_safety.py` | فحص السلامة المعمارية قبل الرفع |
| `masar_styles.css` | تنسيقات الواجهة |
| `data/` | ملفات التشغيل، الجداول، السجلات، الصور، والنسخ الاحتياطية |

## 5. نمط البناء المعتمد: core / wrapper

تعتمد المنظومة الآن على نمط واضح:

- **core**: منطق العمل والحفظ والتعديل، ويوضع داخل الوحدة المناسبة مثل `distribution.py` أو `school_data.py` أو `auth.py`.
- **wrapper**: طبقة Gradio في `app.py`، تستدعي الـcore وتحوّل النتيجة إلى `gr.update` أو مخرجات واجهة.

القاعدة المهمة: إذا كانت الدالة تعدّل حالة محفوظة، يكون `@state_locked` على الـcore فقط، وليس على الـwrapper. هذا يقلل تشابك `app.py` ويجعل المنطق قابلًا للاختبار والتطوير.

## 6. أدوات الجودة والسلامة

قبل رفع أي تعديل يجب تشغيل فحص السلامة:

```bash
python check_masar_safety.py app.py
```

النتيجة المستقرة الحالية بعد مرحلة `3M-final-safety-note`:

```text
PASS: 477 | WARN: 0 | FAIL: 0 | INFO: 6
```

كما تم في مرحلة `4A-hardening` ضبط النشر بحيث لا تتم مزامنة GitHub إلى Hugging Face إلا بعد نجاح فحص السلامة، وإضافة اعتماد `pillow` صراحةً إلى `requirements.txt` لدعم الصور والشعارات.

---

## 7. آلية الحفظ الآمن

تعتمد المنظومة في نسخها الحديثة على حفظ آمن لملفات JSON وفق الآلية الآتية:

1. إنشاء نسخة احتياطية من الملف القديم.
2. كتابة البيانات الجديدة في ملف مؤقت.
3. التحقق من صلاحية JSON.
4. استبدال الملف الأصلي بصورة آمنة.
5. الاحتفاظ بآخر نسخ احتياطية حسب سياسة التخزين.

المسؤولية الأساسية لهذه الآلية موجودة في `storage.py`.

---

## 8. سجل العمليات الحساسة

تسجل المنظومة العمليات الحساسة في:

```text
data/audit_log.json
```

تنبيه مهم لاختبارات الهوية: اسم النظام الذي يظهر في سجل التدقيق يُحفظ في حقل:

```text
source
```

وليس `source_name`. عند اختبار تغيير هوية المنظومة يجب التأكد أن هذا الحقل يعرض الاسم الجديد بعد الحفظ ومن جلسة/دور مختلف.

---

## 9. إعداد مدرسة جديدة

لتجهيز المنظومة لمدرسة أخرى، يفضل تعديل إعدادات المدرسة من مركز البيانات أو ملف:

```text
data/school_config.json
```

بدل تعديل الكود مباشرة. يشمل الملف:

- اسم المدرسة.
- اسم المنظومة.
- الشعار.
- الألوان.
- عدد الحصص.
- أيام الدراسة.
- الأقسام الرسمية.

عند تغيير عدد الحصص قد تحتاج المنظومة إلى إعادة تشغيل لأن `MAX_PERIODS` يُحمّل عند بدء التشغيل.
